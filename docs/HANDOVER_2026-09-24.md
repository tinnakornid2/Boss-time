### 6. Kill Now ยืนยันสองครั้งอย่างถูกต้อง

ปัญหาเดิม:

- Tooltip ระบุให้กดสองครั้ง แต่คลิกแรกส่ง mutation ทันที

ลอจิกใหม่:

1. คลิกแรกจับเวลาและเข้าสู่สถานะรอยืนยัน โดยยังไม่ส่งข้อมูล
2. คลิกที่สองภายใน 1.5 วินาทีจึงส่ง mutation
3. เวลาที่บันทึกคือเวลาจากคลิกแรก ไม่ใช่คลิกที่สอง
4. หากไม่ยืนยันภายใน 1.5 วินาที ระบบล้างเวลาที่จับไว้และไม่แก้ข้อมูลบอส
5. เวลาคลิกแรกใช้ shared server clock offset ไม่ใช่นาฬิกาเครื่องผู้ใช้

Server clock:

- `getDashboardProps()` ส่ง `serverTime` ตั้งแต่ initial page
- `/poll` ส่ง `serverTime` ต่อเนื่องตามสัญญาเดิม
- `public/js/realtime-alerts.js` คำนวณ `state.serverOffset`
- เปิด `window.getTrackerServerNow()` ให้ production bundle ใช้ตอนคลิกแรก
- ไม่มี Firebase read/write เพิ่มใน countdown tick

ไฟล์หลัก:

- `server/server.js`
- `public/js/realtime-alerts.js`
- `public/build/assets/dashboard-B9CVP--8.js`
- `test/realtime-alerts.test.js`

## ขั้นตอนก่อน Deploy

> [!CAUTION]
> **ขั้นตอนนี้สำคัญมากและห้ามข้ามโดยเด็ดขาด** เพราะระบบ Production ใช้เวลา Boss จริงร่วมกันหลายหน้าจอ การนำไฟล์ข้อมูลผิดชุดขึ้นระบบหรือ Deploy โดยไม่ผ่าน Full Test อาจทำให้เวลาบอสคลาดเคลื่อนหรือข้อมูลผู้ใช้เสียหาย

### Mandatory Deployment Gate

ห้าม Commit, Push หรือ Deploy จนกว่าจะผ่านครบทุกข้อ:

- [ ] ตรวจ `git status` และรายการ diff ด้วยตนเอง
- [ ] ยืนยันว่า `server/data/store.json` ไม่อยู่ใน staged files
- [ ] ห้ามใช้ `server/data/store.json` เขียนทับหรือ seed Firebase ที่มีข้อมูลอยู่แล้ว
- [ ] สำรอง `store.json` ก่อนรันชุดทดสอบที่อาจแก้ข้อมูล และคืนไฟล์เดิมหลังทดสอบ
- [ ] ตรวจ SHA-256 ก่อน–หลังการทดสอบว่าตรงกัน
- [ ] รัน JavaScript syntax checks ผ่านทุกไฟล์ที่แก้
- [ ] รัน Full Test ผ่านทั้งหมด รวม Unset, NOW 5 นาที, Still Alive และ catch-up
- [ ] ทดสอบ Preview flow สำคัญด้วย Admin ก่อนแตะ Production
- [ ] ตรวจว่า Deploy เป็นการเปลี่ยนโค้ดเท่านั้น ไม่มี route Reset หรือ data migration ทำงานอัตโนมัติ
- [ ] หลัง Deploy ตรวจ Firebase readiness, `dataRevision`, Active Source และเวลาบอสจริงทันที

หากข้อใดข้อหนึ่งไม่ผ่าน ให้หยุด Deploy และแก้สาเหตุก่อน ห้ามข้ามด้วยการปิด test หรือนำไฟล์ข้อมูล local ขึ้นแทน

1. ตรวจ `git status` และ review diff ทุกไฟล์
2. ห้าม stage `server/data/store.json`
3. สำรองหรือจัดการไฟล์ข้อมูลตามคำสั่งเจ้าของเท่านั้น ห้ามเดาเอง
4. รัน syntax checks ของ JavaScript ที่เปลี่ยน
5. หากมีการแก้เพิ่ม ให้รัน `npm test` ซ้ำตาม Maintenance Contract และยืนยัน Unset, NOW 5 นาที, Still Alive และ catch-up ผ่าน
6. เปิดระบบ local/preview และทดสอบด้วย Admin จริง:
   - Kill Now คลิกแรกต้องไม่เปลี่ยนเวลา
   - คลิกสองภายใน 1.5 วินาทีต้องใช้เวลาจากคลิกแรก
   - ปล่อย timeout ต้องไม่ส่ง mutation
   - ตั้ง Reset Boss Time ให้บอสชื่อซ้ำ Normal/Invasion คนละค่า
   - สลับ EN/TH ขณะ Settings และเมนูเปิดอยู่
   - ตรวจ Tooltip และป๊อปอัปไม่บังรายชื่อบนจอขนาดเล็ก
7. ตรวจ Firebase readiness, browser console, `dataRevision` และ Active Source
8. Deploy ผ่าน GitHub/Vercel เมื่อเจ้าของอนุมัติเท่านั้น
9. หลัง Deploy ตรวจ Production version และ flow สำคัญอีกครั้ง

## งานที่ยังไม่ทำ

- ยังไม่ได้ Deploy หรือสร้าง release/tag ใหม่
- ยังไม่ได้ทดสอบ manual browser flow บน Production
- ยังไม่ได้แก้หรือทำความสะอาด `server/data/store.json` เพราะเป็นข้อมูลผู้ใช้และต้องมีคำสั่งชัดเจน
